# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the versions follow [Semantic Versioning](https://semver.org/). Each change that breaks a call site is listed under **Changed** or **Removed**.

## [Unreleased]

### Documentation
- The READMEs and the guides count five hosts (WPF was missing), show the one-call start of WPF, Avalonia and Uno, and describe the controls written in XAML: MAUI `Shell`, `TabControl` (WPF, Avalonia) and `NavigationView` (Uno), attached with `AttachRouteables`.

### Changed
- `IRouter` is smaller (12 members instead of 14): the three `GoToRouteAsync` overloads (`<TViewModel>(route, ...)`, `<TViewModel>(entry, ...)` and `(entry, ...)`) are extension methods of `IRouter` (`RouterExtensions`, same namespace, so a call site does not change: `router.GoToRouteAsync<MenuViewModel>("MenuView")`, `router.GoToRouteAsync(entry)`). The interface keeps one member for them, `GoToRouteAsync(RouteableRouteRequest, CancellationToken)`, which only `Router` implements; `viewKeys` is kept and travels in the request. A double of `IRouter` that stubbed the old overloads stubs this member instead.
- The samples: the *Lock* page is part of *Features* (its section *Lock*), one page less in the menu; `LockViewModel` and the five `LockView` are gone.
- The samples: the *Saved values* section of the Features page is shown on a phone or tablet only (`IDesktop`), where the system can close the application.
- The samples no longer show the page a guard turned away (*No page is waiting*) and no longer register `RouteableReturn`: the guard of *Members* only redirects to *Features*.
- The samples: the route guard now protects a page of its own, *Members* (a view on every head), instead of Elephants, which opens at once; signed out, *Members* sends the user to *Features*, which now says why, and signing in only signs in, and *Open Members* goes there.
- `RouteParser.SerializationInfos` is private: register a type with `RouteParser.RegisterSerializer(typeName, jsonTypeInfo)`, so nobody can replace or empty the table.
- One suite (`HostContract`) holds the assertions every host owes the application (router, injection rules, dispatcher, no locking, one main view model, value attributes); Blazor, Avalonia, Uno and MAUI run it in `HostContractTests`, WPF in `WpfHostTests` (Windows only).
- A test (`RouteableArgsIsolationTests`) states that the router works on its own copy of the arguments it is given: `Route`, `Router` and `Exception` are never written on the caller's instance.

### Fixed
- MAUI toasts (Android and Windows): the close callback (`onClose`) also runs when the toast goes with its activity or window before it was dismissed, once, as on the other hosts.
- `RouteableContentDialogSession`: a button command that throws is reported through `RouteableErrors` like a click callback, instead of leaving through the event of the host's button; the dialog then closes as usual.
- A page that moves the router itself (its Back or Pop button) now makes the menu follow: `RouteableViewModelBase` listens to `IRouter.Routed` for the moves that are neither a selection nor its own Back or Forward. Back from a page opened by a link no longer stays on that page.
- An address followed with `RouteableDeepLinks.GoToAsync`, and the pages put back by `RouteableLinkInbox.Restore` after the system closed the application, moved the router but not the menu, which kept showing its first page: the main view model is told (`IMainRouteables.OnRouterMoved`) as it is after the Back button.
- Samples: *Open Members*, *Sign in* (back to the page the guard turned away) and *Sign out* went to the page in the router but the screen did not change; the view models now tell the menu (`IMainRouteables.OnRouterMoved`) after a route change they made themselves.
- `/etc/os-release` with a key given twice, or with a comment, no longer makes the detection of the Linux distribution throw (`Distribution`).
- `RouteableModalService` (MAUI): the handler of the close request (`async void`) reports an exception instead of ending the application.
- The unreferenced copies of the renamed subset `LoraDisplay-Regular.ttf` (Avalonia and Razor samples) are removed: the Reserved Font Name "Lora" does not allow them.
- `ShellItems.AttachRouteables` must not be combined with `ShellRoutes.UseShellRoutes` (the address of an item of Shell is also a route, so the selection was cancelled): the XAML shell sample does not call it, and the documentation says so.
- Blazor: the Back and Forward buttons of the browser moved the router and the address but not the menu, which kept highlighting the page it had: `RouteableUrlSync` now tells the main view model (`IMainRouteables.OnRouterMoved`), as `RouteableBack` does. The README of `Routeables.Razor` says who decides the route (`Main.razor`, `@page`).
- The WPF menu (`RouteableListBox`) was white with dark text whatever the theme: the Fluent theme styles a `ListBox` by its exact type, so the menu and its items now take the style of `ListBox` and `ListBoxItem` from the resources.
- The samples use the official `Lora-Regular.ttf` (family "Lora", version 3.021) instead of a renamed subset called "Lora Display", which the SIL Open Font License does not allow under the Reserved Font Name "Lora".
- The Back request of the system (Android button, Alt+Left, mouse) went back in the router but the menu kept showing the page it had: `RouteableBack` now tells the main view model (`IMainRouteables.OnRouterMoved`, implemented by `RouteableViewModelBase`), which shows the current page and selects its entry.
- The `async void` event handlers of the samples (list selection, back buttons, "learn more") catch and trace an exception instead of ending the application.
- A page built for a route change that is not shown (a guard or `CanLeave` refused, a redirect, an exception) is disposed; it was never released.
- A menu entry no longer remembers the page a guard redirected to (it showed the sign-in page the next time the entry was selected), and the menu no longer keeps that entry selected.
- `RouteableState.RestoreSnapshotsAsync` does not give the saved values to the page a guard redirected to.
- A parameter name given twice (a value passed by hand and one of the address, or the same name in two cases) no longer throws when the view is built: the last one is used.
- WPF notifications are placed in pixels of the screen (`NotificationLayout`, `SetWindowPos`) with the scale of the window they belong to, so they sit at the same distance from the top edge and are centred when the monitors of the computer have different scales (the units of `Window.Left` and `Window.Top` are those of the monitor the window is on, not the one it is moved to).
- A synchronous `Dispose` that meets an object that only offers `DisposeAsync` (`ScopedViewCache`, `WeakDisposableTracker`) no longer blocks on it: it starts the disposal and does not wait. Blocking could deadlock a UI thread, and it is impossible on Blazor WebAssembly, which has one thread. The disposal finishes after `Dispose` returns, and an error goes to the error sink.

### Added
- `Routeables.Uno`: `Application.UseRouteables<TMain>(configure, () => new MainPage(), configureWindow)` builds the container and creates the main window in one call from the constructor of the application, so it has no `OnLaunched` to write. The XAnimals Uno sample uses it.
- `Routeables.Avalonia`: `AppBuilder.UseRouteables<TMain>(…, view: lifetime => …)` shows the main view during the setup (or as soon as the application runs when the lifetime is not known yet), so the application needs no `OnFrameworkInitializationCompleted`. The XAnimals Avalonia sample uses it.
- `Routeables.Wpf`: `Application.UseRouteables<TMain>(configure, () => new MainView(), configureWindow)` builds the container and opens the main window in one call, queued on the dispatcher so it works from the constructor, `OnStartup` or `Startup`. The XAnimals WPF sample uses it.
- `Routeables.Maui`: `ShellItems.AttachRouteables(shell, provider)` lets a `Shell` written in XAML (`FlyoutItem`, `Tab`, `ShellContent` with their `Route`) show the routes of Routeables. Each `ShellContent` gets a `RouteableRegion` and is routed on selection; a `Tab` whose `Route` is registered with `AddRegion` has its own history. No `IMainRouteables` (menu, title and lock stay to Shell). Not compiled on MAUI by the author: to check on a device.
- `XAnimals.Maui`: `XamlShell.xaml`, a Shell written in XAML whose pages are the routes of Routeables (`UseXamlShell` in `App.xaml.cs` selects it).
- Samples: a Tabs page on WPF and Avalonia (`TabControl`) and Uno (`NavigationView`) whose items are routes; `MainViewModelWithTabs` adds its entry to the menu of those three heads only.
- `AttachRouteables` for the controls of navigation that the application declares: `TabControl` on WPF and Avalonia (`RouteableTabs`, the route is the attached property `RouteableItem.Route` of each `TabItem`) and `NavigationView` on Uno (`RouteableNavigation`, `RouteableItem.Route` on each `NavigationViewItem`). One region is moved to the selected tab, the router follows the choice of the user and the control follows the router. `RouteTarget` (internal to Routeables.Regions) is what they share. Not compiled by the author: to check on each platform.
- `RouteableRegion` (MAUI): a view still held by another region bound to the same router is released before it is shown (changing the entry of a Shell written in XAML threw on Windows).
- `ShellRoutes.UseShellRoutes(provider)` for MAUI (opt-in): `Shell.Current.GoToAsync("//orders/42")` is routed by the default router when the address matches a route of Routeables; an address that only Shell knows is left to Shell.
- `IMainRouteables.OnRouterMoved(viewModel)` (default: nothing), called when the router moved by something other than a selection of the menu.
- `THIRD-PARTY-NOTICES.md` credits the fonts of the samples (Inter, Lora: SIL Open Font License, texts in `licenses/`; Open Sans: Apache 2.0), the other borrowed files, the packages the samples use, and the trademarks.
- `tools/ImageCredits`: fills the author and license of each photograph of `THIRD-PARTY-NOTICES.md` from Wikimedia Commons, and lists the Wikipedia article each description comes from. The notices now say that the descriptions are CC BY-SA 4.0 text of Wikipedia, not MIT.
- `IRouteGuard` and `RouteGuardDecision` (`Allow`, `Cancel`, `Redirect(route)`): a rule on the page that is entered, written once and registered in the container. A redirect is followed for a `Push` only, and at most 8 are chained.
- `RouteableDiagnostics`: an `ActivitySource` and a `Meter` named `Routeables` (activity `Routeables.Route`, histogram `routeables.route.duration`, counter `routeables.route.redirects`), for OpenTelemetry or a listener of your own.
- The Back button of the system goes one page back on every host (Avalonia, MAUI `RouteablesShell`, WPF `NavigationCommands.BrowseBack`, Uno), through `RouteableBack.TryGoBack` of `Routeables.Services`, which a host of your own can call.
- `RouteableDeepLinks` (an address from outside to a route, through the router) and `RouteableState` (capture the pages of the history as routes, restore them in order), both in `Routeables.Services`. The Avalonia Android sample handles an `xanimals://` link and restores its pages; the WPF sample follows an address given on the command line.
- The Avalonia sample writes the time of each route change to the console (`RouteTimings`).
- `IRouteableState`: a view model writes the values it wants back after the system killed the process, and `RouteableState.CaptureSnapshots`, `RestoreSnapshotsAsync`, `Serialize` and `DeserializeSnapshots` keep them next to the route of each page.
- `RouteableReturn` (`AddRouteableReturn`): a guard that redirects to a sign-in remembers the route it turned away (`RedirectFrom`), and the sign-in takes the user back to it (`Take`).
- `RouteableLinkInbox`: where the addresses and the saved pages that the platform delivers before the container exists wait, and are followed once the first page is shown. The Avalonia, MAUI and Uno samples use it on Android, the MAUI sample on iOS (`CFBundleURLTypes`), and the Uno sample reads a command-line address on the desktop.
- The Back request of the system goes back inside the selected tab first when its menu entry has a `Region` (a history per tab), then in the default router. `RouteableBack.Target` and `RouteableBack.CanGoBack` expose the choice; the WPF `BrowseBack` command and the Uno request follow it.
- `TransitionDuration` on `RouteableRegion` for WPF, MAUI and Uno (the new view fades in; Uno turns on the theme transition). Avalonia already had `PageTransition`.
- Guide *Back, deep links, guards and diagnostics*, which also describes a history per tab (a region per tab) and transitions (the control that shows the page).
- `IRouteableDispatcher` (and `RouteableDispatcherBase` to implement it): a view model asks for it and runs work on the thread of the interface from any thread, whatever the host (WPF dispatcher, Avalonia `UIThread`, Uno dispatcher queue, MAUI dispatcher, the synchronization context of a Blazor circuit). Every host registers it.
- Tests of the WPF host in `Routeables.Test` (`Wpf` folder): the container and its services, the theme, the menu, the lock of a view, `RouteableRegion` and `RouteableRegionItems`, the message box, content dialog, task dialog and modal of a view, the notifications and their placement. They are built and run on Windows, where the project also targets `net10.0-windows`; elsewhere the folder is not compiled.
- The default Blazor layout (`MainLayout`) has a button in its app bar that switches between the light and the dark theme (`MainLayoutBase.ToggleTheme` for a layout of your own). The samples have the same button in the app bar of every head.
- `Routeables.Wpf`, the WPF host (`net10.0-windows`): `Application.UseRouteables`, `OpenMainWindow`, `RouteableFor`, `RouteableRegion`, `RouteableRegionItems`, `RouteableListBox`, dialogs in owned windows and notifications in small windows. It uses the sessions and handle of `Routeables.Services` that the other hosts use, so only the drawing is WPF code. `Runtime.Wpf` identifies it, and the `XAnimals.Wpf` sample has every page of the other samples (animals, History, Regions, Adopt a pet, Lock, Dialogs, About), the `XAnimals.Wpf.Controls` library and the Birds module `XAnimals.Wpf.Birds`. The sample has the icon, the SVG logo (drawn by SharpVectors) and the splash screen of the other heads. The samples now share the Routeables identity: the Avalonia Android icon and splash, the browser favicon, the MAUI and MAUI Hybrid app icon and splash, and the iOS launch screen were those of their templates. The MAUI About logo is a `MauiImage` (it was declared as an app icon, so `logo` did not exist), and the logo of the WPF and Uno samples has no CSS, which their SVG renderers do not read. It was written where WPF could not be compiled: the *Build WPF* job of the CI is its first build.
- `RouteableRegionItems` (Avalonia, MAUI, Uno, Blazor) and `RegionItemsBinding`: a zone that shows every view of a region, in rows and columns, instead of the current one. The samples have an *Adopt a pet* page.
- `IRouter.GoToRouteAsync<TViewModel>(string route, …)`: go to a route by its name and give the view model that builds it.
- Documentation: routing from a hook, reading a template, and the rule that no base view model implements `INotifyPropertyChanged`.

## [1.0.0-preview.1] - not released yet

### Added
- The `Routeables` package (contracts, router, core, regions, segments, locking, service contracts and the source generator), and the host packages `Routeables.Razor`, `Routeables.Maui`, `Routeables.Avalonia` and `Routeables.Uno`; `Reshapes` for MudBlazor, CommunityToolkit.Maui and FluentAvalonia.
- A router with a history (back, forward, pop, root), guards (`CanLeaveAsync`), a lifecycle, results (`GoToForResultAsync`) and events.
- Routes declared by attributes and registered by a source generator (`AddGeneratedRoutes`), typed `GoTo…Async` methods, and AOT and trimming analyzers.
- Regions (`AddRegion`, `RouteableRegion`, `RegionLayout`), segments, page locking, modules loaded on demand (`AddMenuEntries`), and the dialog, notification and theme services.
- Opt-in CommunityToolkit.Mvvm and ReactiveUI flavours of the base view models.
