# Changelog

All notable changes to the Routeables packages. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the versions follow [VERSIONING.md](VERSIONING.md). Every package of the repository has the same version.

## Unreleased

### Changed

- Tests: the members that `IRouter` and `IRouteableArgs` implement by default (`MoveBackAsync` by match and by steps, the positional and named `For…`/`With…` methods, the default region and transition, `GetKeyForContent`) are run by the smallest implementations (`DefaultMembersTests`); `EquatableArray` of the generators, `PersistBag` (a bag that only reads or only writes, a dictionary that refuses writes, a converter, a getter or a setter that throws, and the character, date, time and offset types), and the marking of the generated routes by assembly (`AutoRegistrationEdgeTests`) have their own tests, and so do the injection table merged from a generated registration and the registrations given with an owner.
- Tests: the edges of the generators are tested from Roslyn compilations (`GeneratorsEdgeTests`): the registration generator (no Routeables reference, a `[RouteableView]` without view model or with an array type, `Region` and `Lifetime` given by name, a view model with several constructors, a view without a route, a cached view reported by ROUT201, and the razor check of ROUT204 with a call that has no receiver, a call that is not a name, or a file without text), the analyzer of route literals (ROUT501: no Routeables reference, a route given to a constructor or assigned to a property, types in a namespace or nested, a type that implements `IRouter`), and the coordination generator (callers that are an array, an enum or not accessible, an unresolved caller, a generic or inaccessible destination).
- Tests: `RouteBuilds` (what the registration generator reads of a type) is tested on its own from Roslyn compilations (`RouteBuildsTests`): the constructor that is called or the reasons it cannot be (several public ones, a required member, a generic class, `ref`, `params`, a ref struct, a pointer, `dynamic`), the defaults of the parameters written as literals of their own type, the attributes of the type and of its properties (inherited or not, not accessible, an argument that does not compile), hidden and overridden properties, and the code written by `EmitFactory` and `EmitDescription`. `Routeables.Generated` gives its internals to `Routeables.Test` for it. `RouteableUrlSync` has tests for its failure paths (`RouteableUrlSyncEdgeTests`): a router that throws while the page is prerendered, an address of another site, a menu that refuses or fails, an address that cannot be put back, and a script that cannot be loaded, arrives late or fails when the circuit is gone.
- Tests: the detection of WSL (`DesktopImplementation.IsWsl`) and the reading of `os-release` (`DistributionImplementation.ReadOsReleaseLines`) take the system they read (the variables, the files) as arguments, so that they are tested on any operating system, Windows included; the public behaviour is unchanged.
- CI: the floors of the job "Code coverage" are raised to about three points under the figures of its report: Segments 92 (95.9), Routing 94 (97.3), Regions 93 (96.7), Locking 97 (99.1), Services 92 (95.0), Generated 90 (92.6), Abstraction 90 (93.8), Core 85 (88.8), AspNetCore 94 (97.4), and Routeables.Blazor 83 (85.8) is new. The floor of the whole stays at 65 (66.0): it depends on the hosts, which the tests of this job do not run.
- Tests: the tests of `Routeables.Native` are a project of their own, `tests/Routeables.Test.Native` (plain `net10.0`), run by a new Linux job, "Native tests (Linux)", whose coverage report joins "Code coverage, all the tests". The D-Bus tests and the notifications of Linux need Linux, and `Routeables.Test` runs on Windows, where they were skipped (22 tests): they were not run anywhere, and `SystemNotificationCenter.linux.cs` was at 3%. `Routeables.Test` no longer holds the Native tests.
- CI: the coverage summary lists the files of `Routeables.Native` that no test runs in a table of their own (the other hosts stay in one line), and the line coverage of `Routeables.Native` has a floor of 55% (58.3% once the Linux tests run in their own job).
- Tests: `Routeables.Native` is covered where a platform is not needed. The D-Bus client is tested against a bus that the test plays (replies, error replies, signals, a handler that throws, malformed and big-endian messages, a message of an impossible length, a bus that hangs up, `Skip` of every type, the authentication and the address of the bus over a Unix socket); the notification center of Linux is tested from one end to the other against a notification server that the test plays (`FakeSessionBus`): availability, `Notify` and its replacement of a bubble, refusal, tap, other action, dismissal, signals that are not from the server or not of the right shape, closing, expiration, a server that is replaced and a bus that goes away; and the plain build of `NativeDialogs` and of the center as configured. The tests that need Linux are skipped elsewhere. The macOS (Objective-C), Windows (WinRT), browser, Android and Apple files need their platform and are not covered. `DBusConnection` has one new internal entry for the tests, `ForTestsReading`, which starts the reading thread on a socket that is already connected.

"Reports merged" is one table (a row for each report: the whole, Routing and Core) instead of five long lines, and the table of files that no test runs lists 15 files and leaves out the hosts (Native, WPF, Uno, MAUI, Avalonia), which need a platform to run: one line gives, for each of them, the lines that no test runs. `tools/coverage-summary.py` has two new options for it, `--per-report` and `--files-skip`; the floors are unchanged.

The address synchronization of Blazor (`RouteableUrlSync`) already has tests for the history and the scripts that fail; what is left there are races between a disposal and a script that is still loading.

### Fixed

- **An absolute coordination no longer erases a page that was shown while it was asking**: it asked each router's page whether it could be left, then erased the histories. A navigation of the same router that showed another page in between was erased without being asked. The coordinator now asks again for each router whose page changed (up to three times, then it refuses). A navigation that starts after the last look, between the check and the erasing, is still not stopped: they are not one step, and closing that needs a way to reserve the routers, which is not done.
- **A message of the browser with an `id` that is not a number no longer throws in the page**: `BrowserSystemNotifications` read it with `TryGetUInt32`, which throws on a string; it is now ignored like any message that names no notification shown. Found by a new test.
- `RouteParser.Build` refused an unknown constraint on a catch-all only when the catch-all had a value (`files/{**path:nonsense}` built `files` for no value and was refused for one); it now refuses it in both cases, as for the other placeholders.
- `OnSubscribe` was recorded before it ran: an instance whose `OnSubscribe` threw (a page kept in a cache, entered again by the next try) never subscribed again, and was unsubscribed without having subscribed. It is recorded once `OnSubscribe` has returned.
- Flaky test `A_route_change_is_reported_as_an_activity_and_a_duration_to_whoever_listens`: the activity listener is process-wide, and the test asked for exactly one activity of its page. It now checks every activity of its page.
- Avalonia headless tests: the end of the run no longer waits for ever on the session (closing the main window and disposing the session now have a time limit), so a CI job cannot hang after its tests.
- The Avalonia benchmark (`Routeables.Comparison.Avalonia`) timed out in CI after `Avalonia.Headless` went to 12.1.4 for the tests: it keeps 12.0.1, the version it was measured with.
- Avalonia headless tests: `HeadlessApp.RunAsync` gave Dispatch an async lambda, taken for an `Action`: the dispatch returned at the first `await` of the test, and nothing ran the UI thread (jobs, timers) afterwards, so a test that really waited never resumed. It now gives a delegate that returns a task, which the session waits for while it runs the UI thread.
- Avalonia headless tests: a test that really waits (`Task.Delay`) never resumed, because nothing ran the jobs of the UI thread once the dispatch had returned. `HeadlessApp.RunAsync` now starts the test and runs those jobs itself until it ends.
- Avalonia headless tests: the first test closed the first window shown, which is the main window of the application, so Routeables disposed the container and the next tests failed with `ObjectDisposedException`. The session now opens a main window of its own, makes it the active one before the first test (Routeables is started after the session does, and takes the window that is active then for the main one), and keeps it open until the end.
- The Avalonia headless tests failed with a `TypeLoadException` (`SetFrameThemeVariant`): `Avalonia.Headless` was 12.0.1 while the application loaded Avalonia 12.1.4. Headless and Fluent now use the same version as the rest (12.1.4).
- **The Avalonia headless tests passed without running their body.** `HeadlessApp.RunAsync` returned when the dispatch did, while the test was still running, so the dialog tests passed with their assertions never checked (which is why `DialogPresenter` showed 0% coverage). It now waits for the end of the body and reports its failure; the tests that fail once checked are fixed next.
- Flaky test `Of_several_route_changes_waiting_only_the_last_one_runs`: the ten route changes now wait for a release, so none can finish before the others have asked (on a loaded machine the first ones could finish before the last ones started, and were then not replaced).
- CI warnings: the test projects (`Routeables.Test*`) no longer generate XML documentation, so their test methods stop raising CS1591; the workflows use the Node 24 versions of `setup-dotnet` (v5), `upload-artifact` (v7) and `download-artifact` (v8).
- **The dialog window of Avalonia no longer shows in a corner before it is centred**: it opened at (-32000, -32000) and was moved once its size was known, which a system may undo (Wayland, macOS) and which was seen on screen. It now opens transparent on its owner and is made visible once it is centred.
- **Two threads that build views which need each other no longer block for ever** (`ScopedViewCache`): X is being built and asks for Y while Y asks for X. The circular dependency was only seen on one thread; across two, each waited for the lock of the other. One of the two now fails with the same `InvalidOperationException`, the other finishes.
- **Blazor notifications: a failed start is not kept**: when the import of the module or the registration of the service worker failed, the failed task stayed in the cache and every later call failed with it, and the reference to the module that was loaded was never given back. The next call now starts again.
- **`RouteCoordination.Parse` and `RouteSegment` refuse what the builder refuses**: a segment named `.`, or `..` written escaped (`%2E%2E`, which was read as the way back). Only a plain `..` is the way back.
- **`os-release`: the escapes of a double-quoted value are decoded** (`\"`, `\\`, `\$`, `` \` ``), as the specification says.
- **`AddRegion` refuses `ServiceLifetime.Transient`**, as `RegisterRouting` does: each resolve of a transient region got a history of its own, so the pages shown were lost without a word. It throws an `ArgumentOutOfRangeException` at registration.
- **Two test classes no longer disturb each other through `RouteableErrors.Default`**: `RouteableLinkActionTests` replaces that process-wide default while `RouteableErrorsGuardTests` listens to what goes to it, so under parallel runs one saw the reports of the other (a missing trace, three reports instead of one). Both are in one xUnit collection, and the link test counts only its own report.
- **`EraseHistoryAsync` told the page it was left after disposing it**: `OnLeftAsync` ran after `OnUnsubscribe` and `Dispose`, so a transient page that gave back a resource there got an `ObjectDisposedException` (reported, the clean-up half done). `OnLeftAsync` now runs first, as in every other route change.
- **`RefreshGuardsOn(source, provider, null)` no longer ends the process**: an explicit `null` for the list of properties was read in an `async void` handler and raised a `NullReferenceException` at the next `PropertyChanged`. It now means every property, as an empty list does.
- **The two tests of the end of an asynchronous disposal no longer wait for the thread pool** (`Task.Yield` and a ten second poll failed when the pool was busy with the rest of the run): the disposal waits for a gate that the test opens, and the test waits for its end.
- **Under `CancelCurrent`, a route change that has to replace the one in progress takes its place in the queue first**, then asks the other to stop, and takes its turn after the callers that come right after it: when the operation in progress ended as soon as it was asked to (its cancellation runs on the spot), the caller went in at once and ran, so ten changes started one after the other all ran instead of the last one only.
- **The views and view models of the tests that had an attribute above them** (`[Authorize]` on `PrivateVm`, `AdminVm`, `SignInVm`) **lost it** when the tests were gathered in `Fakes` (the roles of `RouteableAuthorizationGuardTests` were no longer asked): a type with an attribute or a comment above it stays where it is.
- **`Routeables.Maui` builds for Android on Windows again** (`CS0117: SystemNotificationCenter does not contain HandleIntent`): `Routeables.Native` left out its Android and Apple targets on every Windows machine, so the Android build of MAUI got the plain `net10.0` one. Only the GitHub runner, which has no such workload, keeps the two targets.
- **The coverage summary lists the files that tests reach least** (`tools/coverage-summary.py --files N`), and can hold a floor for one assembly (`--min-assembly`); more headless tests of the Avalonia pages, the headers, the drawer and the automation peers.
- **`EraseHistoryAsync` tells the page shown that it is left** (`OnLeavingAsync`, then `OnLeftAsync`): a page kept by a cache was entered twice in a row, and what it took in `OnEntering` was never given back.
- **A `RouteSegment` that pushes a view cannot be named `..`, and a `RouteCoordination` cannot be empty**, whoever builds them (the records are public), not only the builder.
- **A generated method of a route with optional values only and a query** writes `/?q=x`, as `RouteParser.Build` does.
- **The lifecycle guide says what the router does** when the view of the page left fails in `OnLeavingAsync` (the view model is entered again, the view is not).
- **A declared query parameter that is sent empty** (`/search?q=` for `search?{q?}`) is no longer given to the hooks as an undeclared value.
- **`check-packages.sh` no longer fails, or passes, by chance**: `grep -q` stopped `unzip` with SIGPIPE under `pipefail`.
- **The wait for the first page uses a monotonic clock**, not the system time.
- **The re-evaluation of the guards (`RefreshGuardsOn`) no longer cancels the route change in progress** under `RouterConcurrency.CancelCurrent`: it waits for it, and a refresh that is replaced is not reported as an error.
- **A parameter of the caller replaces the one of the menu entry that has its name**, for the constructor and the view as it already did for the values (the constructor and the property read the same one).
- **A segment of a coordination cannot be named `..` or `.`**: written `..`, it was read back as the way back. The documentation of `RouteCoordination` says that a `/` in a value of a hand-written address is `%2F`.
- **A route change started by work that nobody awaits waits for its turn** (`RouteableHelper.FireAndForget` from `OnEnteringAsync`, `RefreshGuardsOn` raised during a route change): it copied the mark of the route change in progress and was refused as "Reentrant route changes are not supported". A nested change that is awaited is still refused.
- **A value named in `viewKeys` reaches the property of the view**, as documented: it was marked as a constructor argument and, without a matching constructor, lost.
- **The positional `RegisterRoute<TView, TViewModel, TArg1, …>` read the arguments of the constructor by their place among the constructor arguments**, not among all the entries (a property entry before them gave the wrong value).
- **The address and the caller no longer both give a value of the same name to the constructor**: the value of the address replaces the one of the caller, as it does for the property.
- **The not-found page receives `notFoundUrl` once**, even when the caller's args already held one.
- **A route registered again for another view model follows the last registration**, as the container does for the view: the table kept the first view model, so the view of one page was shown with the view model of the other.
- **`GoToRouteAsync<TViewModel, TData>` fails when the route does not reach a `TViewModel`**: the data was dropped and the result was a success.
- **`<routeable-menu>` marks an entry whose route is written escaped** (`/caf%C3%A9`) when the page is `/café`.
- **A named value is there once**: the value of the address, or of the caller, replaces the one of the menu entry that has its name (without the case) instead of being added next to it, so that `Get<T>` no longer fails with "2 values are named" (a link with `?tab=` on an entry with a `tab` value, and the restore of the saved history).
- **The link that opened the application is no longer lost when the first page is shown late**: the pump of `RouteableLinkInbox` started from a `Routed` handler carried the navigation lock of the change in progress and was refused as a reentrant route change. It starts without that context.
- **A menu entry whose template is written `about` for a page registered as `/about`** finds its view: the entry takes the spelling the page was registered with.
- **`RouteBuilder.Tab` without a route is `/home` for a `HomeViewModel`**, as documented (or the `[Routeable]` path of the view model): it registered the internal key of the view as an address.
- **A selection of the menu that is cancelled while it waits gives the current version back to the newest selection that is still alive**: with A running and B, C waiting, cancelling B then C made A think it had been replaced.
- **The generated `GoToXxxAsync` refuse a path value with a `.` or `..` piece** (`a/..`), not only the value `..`.
- **A generated method of a route with optional values only goes to `/`** when none is given (the router refuses an empty address).
- **`GoToAsync<TViewModel>(values)` returns a failed result** when a registered serializer cannot write a value, instead of throwing.
- **The generated `GoToXxxAsync` refuse what `RouteParser.Build` refuses**: `.` and `..` as a path value, NaN and infinity for a `double` (an `ArgumentException`, as for an empty piece of a catch-all).
- **`RouteParser.Build` treats a value whose text is empty as missing** (an empty `StringBuilder`): it wrote `/a//b`, which does not read back.
- **ROUT501 only checks the `GoToAsync` of the router** (and its `IServiceProvider` extension), not the one of another library.
- **`RouteableAddress.Of` keeps the escapes of a route** (`/tags/c%23`, `?q=a%26b`): the implicit string to `PathString` conversion decoded them.
- **A constructor with parameters that differ only by case** (`int id, int Id`) no longer crashes the binding by name: the first one keeps the name.
- **A view whose `OnLeavingAsync` fails is not entered a second time**: the recovery enters again only the view model, which was the one that had left.
- **`RouteParser.Build` writes `-0f` as `0`**, as it already did for a `double`.
- **`RouteParser.Build` refuses a template whose catch-all is not the last segment** (`/files/{**path}/edit`): it wrote an address that the router refuses to read.
- **ROUT501 no longer reports valid routes**: an address with a fragment (`#top`), with an escaped literal (`/mon%6Beys`) or that leaves out an optional value followed by a catch-all (`/cat` for `/cat/{age?}/{**rest}`).
- **The default menu starts again after a failed first try**: `Start` kept its flag when the home route could not be opened, so it never tried again.
- **The address of the D-Bus session bus is unescaped** (`%hh`), as the specification says.
- **The guide says which optional placeholders are accepted**: none followed by a required segment; the generated `GoTo…Async` methods are stricter (the optional one must be the last).
- **The link that opened the application is followed when the first page comes late**: the inbox gave up after 30 seconds without a page and kept the link until another one came; the first page that is shown now starts it again.
- **A value of the arguments is found without the case of its name** when the exact name is not there (`?Ref=mail` is read by `args.Get<string>("ref")`), as a query is read everywhere else; the exact name still wins.
- **The detection of the Linux distribution survives a file it cannot read**: an error on `/etc/os-release` was kept for the whole process, and `/usr/lib/os-release` (the second place of the specification) was never tried.
- **A plus in the query of a coordination written by hand is a space**, as for a route (`%2B` is a plus, which is what `ToString()` writes).
- **The saved history is put back when the first page comes late**: the keeper gave up after 30 seconds without a page, turned itself on and wrote the next route change over the file with one page. It now waits for the first page as long as it lives, and nothing is written before the pages are back.
- **`RouteParser.Build` gives `/` for a template of optional values with none given** (`{tab?}`), not an empty route that `GoToAsync` by view model refused.
- **A value that cannot be saved no longer leaves the old one behind**: `PersistBag.Set` wrote nothing for a text over `MaxValueLength`, a type that is not supported or a converter that gives `null`, and the key of an earlier save stayed in the dictionary, so the old value came back at the load. The key is removed.
- **`[Persist]` does not write what it cannot read back**: a value whose type is not the declared one (an `int` in a property of type `object`) and an enum number that names no member were written (the save said it worked) and came back as nothing or as `0`; they are not written now.
- **"No route matches" names a template written with a misplaced placeholder**: `/users/{id?:int}` (for `{id:int?}`) and `?q={q}` (for `{q}`) are read as fixed text, and the message told to register a route that was registered. It now names the template and the piece, and how a placeholder is written.
- **`GetModalFor<TViewModel, TResult>()` finds the view without a `route`**: it looked for the view under the name of the view model type, a key nothing is registered under, so the call always failed; it now uses the key the view is registered under, as `ShowModalAsync` does.
- **Uno and WinUI 3: `RouteTransitionDuration` alone plays the theme transition**: an unset `RouteTransition` was read as the transition "None", so the fall back on the duration never happened; the other hosts already ignored a blank name.
- **`RouteableLinkInbox` does not spin when no router is registered**: it started its pump again and again; it now stops, as it does when no page ever comes.
- **The contract of `GetViewModel` says what it does**: it gives `null` when nothing is registered for the key (a view without a view model), it does not throw.
- **A second `RouteablePersistence.Save` into the same dictionary writes again**: the rule that keeps the value of the most derived class for a hidden property (the last fix) kept the first value of a dictionary that already had the key. The names are now those of one pass, and a name is taken class by class.
- **A property hidden by `new` is not given the value of the class that hides it**: the base class read the same key as the derived one (a `7` became `42`); it no longer reads a name that a more derived class took.
- **A property named like a keyword compiles in the injection code** (`@event`), as it does in the other generated code.
- **A catch-all with a default value can be left out of a generated `GoToXxxAsync`** (`/files` is a valid address of `/files/{**path}`, and `FilesViewModel(string? path = null)` is the way to say so); it used to throw.
- **The generated catch-all refuses what `RouteParser.Build` refuses**: an empty piece (`a//b`), `.` and `..` raise an `ArgumentException` instead of being dropped.
- **`RouteAddress.Same` reads the query of an address that has a brace nothing closes** (`/notes/a{b?x=1`) as it always did: only a brace that is closed hides a `?`.
- **A converter registered for a nullable type is used to read as well as to write**: `RegisterConverter<DateTime?>` wrote the property and the read looked for the type under it, so the value was lost at the restore. Both sides look the type the property declares first (then the type under a nullable); a converter of a subclass is no longer used to write a property of its base type, which the read could never find.
- **A `[Persist]` property hidden by one of the same name** (`new`) keeps the value of the most derived class: the base class used to write over it under the same key.
- **`[Persist]` on a property of a struct is reported** (ROUT401) instead of producing generated code that does not compile.
- **The menu follows a move between two routes served by one instance**, not only between two instances.
- **`RouteAddress.Same` reads the query of a template with an optional parameter**: the order of the pairs of `/p/{tab?}?a=1&b=2` does not count, as for any address.
- **A page that is its own view model is asked once**: `CanLeaveAsync`, `OnLeavingAsync` and `OnEnteringAsync` ran on the view model and then on the view, which is the same object for a route registered without a view model: a confirmation to leave was shown twice and a load ran twice.
- **`RouteAddress.Absolute` keeps the `?` of an optional parameter in the path** (`products/{tab?}/` is `/products/{tab?}`), as `PathOf` does since the last fix, and so does the comparison of the words of a template.
- **A `[Persist]` property named like a keyword compiles** (`@class`): the generated code writes the `@`.
- **The guide of `IRouteTypeGuard` says that a rule that depends on the visitor must also be an `IRouteGuard`**: a page shown again from the history or from a menu entry is not asked of the type guards.
- **`[Persist]` reads back what it writes for `Int128`, `UInt128`, `nint` and `nuint`**: the codec wrote them and the read side did not know them, so the value was lost at the restore without a word.
- **`RouteAddress.SamePath` follows the rules of its class**: an escaped path (`/%C3%A0-propos`) is the one written plainly and an empty segment does not count, so a menu page is found by a deep link written either way; and `PathOf` no longer ends a template at the question mark of an optional parameter (`products/{tab?}`).
- **The case of a value that holds an escaped `?` or `#` counts**: `RouteAddress.Same` looked the template up with the unescaped path, which the parser cut at the question mark, so `/x/q%3F/B` and `/x/q%3F/b` were taken for one page. The two characters are escaped again for the lookup.
- **In a query, `/` and `%2F` are the same**: `?dir=a/b` and `?dir=a%2Fb` (what `RouteParser.Build` writes) are one address, as the parser reads them; in a path an escaped slash stays a character.
- **A history keeper disposed before its restore starts no longer holds the deep links**: `EndRestore` is called on that path too, so `RouteableLinkInbox` does not wait for ever.
- **Two routes that differ only by their query are both registered**: the table of routes dropped a route whose path was already there, so `/search?mode=grid` registered after `/search` (or `/search` after it) was lost without a word. The table now compares the whole template, and the type guards and the template lookup of an address take the template that is the route itself before the one that has the same path.
- **A Blazor address without the closing slash of the base** (`https://site/app` for the base `https://site/app/`) is the application, not another site: the guards can refuse it before the navigation happens.
- **The example of `RefreshGuardsOn` compiles**: it passed the property name where the `provider` goes.
- **A menu whose `GetEntries()` reads a field of the derived class says why it failed**: `GetEntries()` runs while the base class is constructed, so a field or a constructor parameter is still null; the `NullReferenceException` (or `ArgumentNullException` when the null field is handed to a method) is now an `InvalidOperationException` that names the cause and the way out (`initialize: false`). The guide and the remarks of the class say it too.
- **The generated `GoToXxxAsync` write a number with one text**: `GoToProductAsync(router, 19.90m)` wrote `19.90`, which the parser refuses since a number has one text (the call failed with "not a valid decimal"); a `decimal` is now written without its trailing zeros and a `double` `-0.0` as `0`, as `RouteParser.Build` does.
- **An escaped literal is found in a table of eight routes or more**: the index by first segment held the raw text of the template (`my%20page`) while the address is looked up unescaped.
- **A fixed query entry written escaped in a template is read back** (`/x?mode=a+b`): the address is decoded (a plus is a space) but the template text was compared raw.
- **`RouteAddress.Same`: `/a//b` is `/a/b`**, as the parser reads it (empty segments are skipped), so Blazor does not synchronise the URL for nothing. The case of a query value still counts: a value that a placeholder binds keeps its case.
- **A menu page opened with a query keeps its address**: `GoToAsync("/about?ref=x")` to a menu entry with no template wrote the address of the entry (`/about`) in the history, so Blazor could rewrite the address bar without the query. The address asked for is the route of the change (the query values are still in `Values`).
- **`{n:double}` has no `-0`**: `/x/0` and `/x/-0` were two addresses; `-0` is refused and `Build` writes `0`.
- **A literal written escaped in a template matches**: `/my%20page` was compared to the unescaped segment `my page` and never matched, although `Build` writes it as it is.
- **`RouteAddress.Same` no longer confuses `%2F` with the character U+FFFF** (`%EF%BF%BF`): the escaped slash was replaced by a marker that a text can also decode to; the pieces are now unescaped one by one and joined by `%2F`.
- **D-Bus, a variant nested too deep or a signature of several types is refused** (`InvalidDataException`, the message is dropped): the unbounded recursion could overflow the stack, which cannot be caught.
- **The query of the address counts when two templates have the same path**: `/search` and `/search?{q?}` (or `/search?mode=grid`) matched `/search?q=1` with the same score and the order of registration decided, so a value the address gave could end in `Values` instead of the constructor. Between equal paths the template that uses more of the query of the address now wins, whatever the order.
- **A typed menu entry whose address is not its template finds its view**: `new RouteableMenuEntry<OrderVm>("Order 5", route: "/orders/5", template: "/orders/{id:int}")` looked the view up by the address (`No view is registered under the key "/orders/5"`); the keys come from the template, as everywhere else.
- **`RouteableMenuEntry<T>` takes the route of its view model, as documented**: with no `template` (a `route` only) the template is the one the address matches; with neither, the registered route of the view model. Both held an internal key before, and the entry always failed.
- **The type guards (`IRouteTypeGuard`) are asked for a page registered with no route**, opened from a menu: it is not in the table of routes, so the guard was skipped and the constructor ran. The type of the request is used when the table does not know it.
- **A `decimal` has one text**: `1.50` and `1.0` are refused (`1.5`, `1` are the texts), and `Build` writes a decimal without its trailing zeros. A `bool` is still read in any case and a `Guid` in upper or lower case on purpose: links written by hand and by other tools use both.
- **`ScopedViewCache`: a circular dependency is an error**: a constructor that asked its own cache for its own key built again, for ever, until the stack overflowed (the lock is re-entrant). It now throws `InvalidOperationException`, and the key can be built afterwards.
- **ASP.NET Core, the buttons of a task dialog are translated**: `ShowTaskDialogAsync` wrote the name of the enum value, the other hosts go through `RouteableTexts.Button` (the translator of the application).
- **The generator leaves out a `[Routeable]` view model it cannot reach** (private nested class, internal in another assembly): `ROUT207` instead of code that did not compile (CS0122).
- **`-/orders` shows the page that was left again when the route throws or is cancelled**, not only when it returns a failure (`GoToAsync`); the exception goes on.
- **D-Bus, a big-endian message is dropped instead of closing the connection**: its lengths are read and the message skipped.
- **`ScopedViewCache` keeps the page of a caller that waited for a failed construction**: when the constructor of a scoped or singleton page failed, the entry was removed from the cache; a second caller already waiting on it then built the page into that removed entry, so the cache did not own it (two "singleton" pages, one never disposed). A failure now keeps the entry: the waiting caller builds the page under the same lock and the cache keeps it.
- **`/files/a%2Fb` and `/files/a%252Fb` are two addresses** (`RouteAddress.Same`): the parser reads the values `a/b` and `a%2Fb`, but the comparison gave the same text for both, so the URL synchronisation of Blazor could ignore a real navigation.
- **`{**path}` is built only from a value it can read back**: `a//b/` became `/a/b` with no word; a value with an empty segment (doubled, leading or trailing slash) now throws `ArgumentException` in `RouteParser.Build`, like a `.` or `..` segment.
- **A name used twice in a template is refused**: `/dup/{id}?{id}` gave the path value to both and lost the query one. Such a template never matches (the reason says why) and `Build` throws.
- **The generator leaves out a `[Routeable]` open generic or `file` view model** with a warning (`ROUT207`) instead of code that did not compile (CS0246); a `[Persist]` property of a `file` class is reported (`ROUT401`) and skipped instead of code that did not compile (CS0234).
- **`{n:double}` keeps its one text** (see the previous entry on numbers), so `1e5`, `2.5e2`, `7.0` and `007` are refused: write `100000`, `250`, `7`. The test that still used `2.5e2` was changed; the guide says it.
- **ASP.NET Core, an answer names its dialog**: the answer was only a button index applied to whichever dialog waited, so with a double click on "Yes" the second request answered the next dialog with the button of the first (two tabs of the browser could cross in the same way). `RouteableDialog.Id` is sent back by the form, `RouteableInteractions.AnswerAsync(int, long)` and `ContinueAsync(Action, long)` ignore an answer to a dialog that is not the one that waits, and a second answer to the same dialog is ignored too. `AnswerAsync(int)` is unchanged and keeps its limit (documented); the sample posts the number of its dialog.
- **The generator no longer walks every type of every referenced library**: it reads fully the assemblies that reference the one of the attributes (they are the only ones that can hold a `[Routeable]` type), and for the others (controls, mapping, logging...) looks only at the names of their types for the views the view models ask for (`ShopView` for `ShopViewModel`); a `ListView` of a third-party library is no longer a candidate. A nested view of such a library is no longer paired by name (use `[RouteableView]`).
- **`GoBackToRootAsync` on the root discards the entries after it**: with the cursor on the first entry and others after it (it had gone back to it), the call was cancelled and kept them, and their pages, while from any other entry it discards them (`Router`).
- **`ScopedViewCache` no longer runs a constructor under its lock**: a constructor that waited for another thread which asked the cache for something blocked it; the constructor now runs under the lock of its own key, still once per key. A cache disposed while a page is built disposes that page. A single failure to dispose keeps its own stack.
- **`{n:double}` has one text too**: `7.0`, `07`, `1e3` and `1.50` are refused (`7`, `1000`, `1E+20`, `1.5` are the texts `ToString` writes), like for the other numbers; `/x/7` and `/x/7.0` were two addresses for one page.
- **`{id:int?}` ranks before `{tab?}`**: a typed optional placeholder is more specific than an untyped one, whatever the order of registration.
- **`.` and `..` are not segment values**: `Build("/users/{name}/edit", name: "..")` wrote `/users/../edit`, which a browser resolves to `/edit` (`%2E%2E` too), so Blazor showed one address and routed another. `Build` refuses such a value (and a catch-all that has such a segment) and an address with one does not match; a query value (`?dir=..`) is not a segment and is unchanged (`RouteParser`).
- **`RouterConcurrency.CancelCurrent`: a caller cancelled by its own token no longer replaces the others**: with A running and B waiting, a C that was then cancelled had already cancelled A and made B give up, so nobody ran. The last caller that is still wanted wins, and a caller that is already cancelled replaces nobody (`RouterGate`).
- **`GoToAsync<TViewModel>` with a `Dictionary<string, int>` (or any `string`-keyed dictionary)** reads its entries: the object overload read its properties (`Count`, `Keys`...) and answered "needs a value for {id}" (`RouteParser`).
- **A template given without its first slash is the registered one**: `GoToAsync("/about", template: "about")` failed when the route was registered as `/about` (`Router`).
- **A route value the view model does not ask for is left out by reflection too**: `RegisterRoute<TView, TViewModel>(route: "/tabs/{tab:int}")` with a view model that takes no `tab` failed with "a suitable constructor could not be located", while the generated code ignored it (`RegistrationExtensions`).
- **Blazor, a Back of the browser that a newer route change replaced (`CancelCurrent`) is not reported as an error**, and the address is not rewritten: `OnLocationChanged` treated its cancellation as a failure, `OnLocationChanging` already did not (`RouteableUrlSync`).
- **`Routeables.Native` on Windows builds its desktop targets only** (`net10.0` and the Windows one): the Android and Apple targets it asked a Windows machine to restore need workloads that are not there (NETSDK1147), which failed the build of `Routeables.WinUI3` in CI. The packages are still packed on Linux with all the targets.
- **Blazor, an address nobody serves shows the page of `UseNotFoundRoute()`**: `RouteableUrlSync` did nothing for it (a link changed the address bar and kept the page before, the first start opened the first entry of the menu); it goes through `GoToAsync` now, like any other address. Without a not-found page nothing changes.
- **A tab or a line break does not hide the second slash of `//host`**: a browser drops them, so `/<tab>/evil.example` was `//evil.example` for it, and `RouteAddress.Rooted` and `RouteableAddress.Of` let it through.
- **Two registered types with the same simple name as a built-in constraint (`Sales.Guid` and `Hr.Guid`) no longer disable `{id:guid}`**: the ambiguity of the name was checked before the built-in constraints.
- **`RouterConcurrency.CancelCurrent`: a newer route change that arrives while the gate is held and the operation not yet published cancels it**, as the documentation says (it found nothing to cancel, and the older one ran to its end first).
- **`GoToAsync` looks for the route with the address trimmed**, like it reads the qualifiers (`-`, `-/orders`).
- **Documentation**: the routes the generator registers break a tie in the alphabetical order of their view models, not in the order of declaration.
- **Blazor, a link to `/` from a page that has no route goes to the home registered on `/`**: such a page is shown under `/`, and the link was taken for the page that is shown, so the router did not move (`RouteableUrlSync`; only for a link the user clicked, what the router itself writes is still ignored).
- **ASP.NET Core, a request waits for the dialog of its own action**: the signal "the action asked something" was one per visitor and replaced by each request, so with a double click or two tabs the dialog of request A woke request B and A stayed pending. The signal now belongs to the action (`RouteableInteractions`).
- **A converter of the application that fails with any exception is an address that does not match**: only `JsonException` was caught, so another one came out of the search for a route for every address (`RouteParser`).
- **`{n:decimal}` has one text too**: `007` and `01.5` are refused, like for the integers.
- **A constructor parameter takes the value that has its name**: with `ProductViewModel(string category = "all", string id = "")` and `/products/{id}`, `/products/42` gave `category = "42"` and `id = ""`, because the values were handed out by type only. A value is now given to the parameter of its name first, and by type only to the parameter that no named value claims, with the generated code and with the reflection (`ConstructorArguments`, `RegisterRoute`).
- **The generator writes the defaults of the constructors as literals of their type**: `float zoom = 1.5f`, `decimal price = 9.99m`, `double.NaN`, the infinities, `long.MinValue` and a negative enum value (`(E)(-1)`, not `(E)-1`) gave code that did not compile (`RouteBuilds`).
- **A registered type named `Guid`, `String`, `Double`, `Decimal`... no longer replaces the constraint of that name**: `{id:guid}` kept reading JSON once such a type was registered; the built-in constraints come first, and the type is reached by its full name (`RouteParser`).
- **A value has one text in an address, for the types that remained**: `{n:int}` and `{n:long}` refuse `007` and `-0` (the text `ToString` writes is the only one), `{g:guid}` takes the form with dashes only (no braces, no form without dashes), and `{b:bool}` refuses spaces around the word.
- **The fragment of an address is not sent to the telemetry** (`IncludeAddress`): `/cb#access_token=...` of an implicit OAuth flow went out with the route.
- **Two queries whose names are escaped differently are the same address** (`?%7A=1&b=2` and `?z=1&b=2`): the pairs were put in order by the escaped name and compared by the unescaped one (`RouteAddress`).
- **Blazor, `RouterConcurrency.CancelCurrent`**: a route change that a newer one replaced is no longer reported as an error by `RouteableUrlSync` (its cancellation does not carry the token of the browser).
- **`RouteableState.RestoreAsync` (the routes only) stops at the first page a guard sends elsewhere**, like `RestoreSnapshotsAsync` does: with a guard that redirects to the sign-in page, `[/home, /orders, /orders/42]` came back as `[/home, /login, /login]`. It now is the same restoration, and a list of commands only (`-/orders`) no longer erases the history before finding nothing to show.
- **A number has one text in an address**: `{n:int}`, `{n:long}`, `{n:decimal}` and `{n:double}` no longer accept a plus sign, a space around the number or a thousands separator, and `{n:double}` no longer accepts `NaN` or `Infinity`; `42`, `+42` and ` 42` were three addresses for one page.
- **Diagnostic ROUT206**: two `[Routeable]` view models that declare the same route (the case and a trailing slash do not tell them apart) are reported; the second was ignored by the table of routes and failed later with a message that did not say why.
- **Documentation of what a route change throws**: an exception of your own code (a guard, a view model constructor, a lifecycle hook) and the cancellation of a route change reach the caller, they are not turned into a result; a route change started from `OnEnteredAsync` or `OnLeftAsync` is refused and only written to the debug output; `-/orders` on the first page is cancelled.
- **A singleton of a module loaded while running is built with the application's container**, not with the scope of the first visitor that reached it: on Blazor Server, what it took from that scope (the router, the authentication state) was served to every other visitor (`RouteableModuleServices`).
- **The generator finds the pages of a library whose name only starts like a framework** (`AvaloniaShop.Features`, `PresentationLayer`, `SystemMonitor.Pages`, `MudBlazorKit`): the prefixes of the frameworks are matched whole or followed by a dot, and those libraries were skipped without a message (`RouteRegistrationGenerator`).
- **`{id:String}` ranks as untyped**, like `{id}` and `{id:string}`: its case was not read by the ranking, so it tied with `{id:int}` and the order of registration decided where `/a/42` went (`RouteParser`).
- **`packages.json`** (the output of `dotnet list package`, with a local path) is no longer in the repository, and is ignored.
- **Blazor, a link to the page before or after the current one** is a new page for the router, as it is for the browser: the router pushed nothing and went back (or forward) instead, and its history no longer followed the one of the browser (`RouteableUrlSync`: only the Back and Forward buttons of the browser move the router through the history now).
- **Restoring a saved history stops at the first page a guard sends elsewhere**: with a guard that redirects to the sign-in page, `[/home, /orders, /orders/42]` came back as `[/home, /login, /login]` (`RouteableState`).
- **`RouteParser.RegisterSerializer`**: a type with no namespace keeps its name when a homonym of a namespace is registered; its simple name is its full name, it was the only name it had, and it became ambiguous.
- **`RouteParser`** no longer builds the set of view keys when there are none, the set of bound names when the address has no query, nor a dictionary for an empty query: about 250 B less per route change.
- **Finding a route no longer costs a pass over every template**: `RouteParser.BestMatch` indexes the table of routes by the first literal segment (`/p00`, `/detail/...`) and tries only the templates that can open the address (the same literal, and the ones that start with a placeholder), in the order of registration, so the tie between two equally specific templates is broken as before. And the question "does this template match" (`TryMatch` without arguments) no longer builds an error message, a set of bound names or a set of view keys. Measured on the parser alone: a route change with 201 templates went from 126 KB and 136 µs to 0.5 KB and 1.2 µs, and no longer grows with the number of routes (below 8 templates the table is read as before). The reason of a mismatch is unchanged (`Mismatch`).
- **`RouteParser.Build`**: a `{**rest}` after an optional that was left out is refused, like any later value (it built `/cat/a/b`, which the router read as the age).
- **A view that cannot be built no longer leaks its view model**: the view model the route change had already built is disposed (`Router`).
- **`RefreshGuardsAsync` with `RouterConcurrency.CancelCurrent`**: the redirection stops when the caller cancels; it used a token that was already released.
- **`RouteAddress`** reads addresses as the parser does: the fragment (`/about#top`) is left out, a plus in a query is a space (`?q=a+b` is `?q=a%20b`), and `Absolute` keeps the end of the query (`/files?dir=/`).
- **`RouteableState.RestoreAsync`** ignores a saved route that starts with `-` (go back), as `RestoreSnapshotsAsync` does.
- **Linux notifications**: when the bus closes or the notification server is replaced, the identifiers it gave are forgotten and the notifications that were waiting end as dismissed (the next server could have replaced the bubble of another application with one of them).
- **`BrowserSystemNotifications.DisposeAsync`** (Blazor) catches the same exceptions as the other services of the browser.

A text that was changed or written with another key is left out and the application starts with no history. The history holds the addresses and what the pages saved (`[Persist]`): without a protector it is still plain text, as before; **adding a protector to an application that already has a plain history starts it empty once.** `FileRouteableHistoryStore` also writes its file for its owner only (mode 600) on Linux, macOS and Android.

- **System notifications on the Linux and Windows desktop** from the plain `net10.0` build of `Routeables.Native` (Avalonia, WPF, a console): Linux through `org.freedesktop.Notifications` on the D-Bus session bus (a small client inside the library, no package: a tap on the notification is a tap, closing it a dismissal), Windows through the toasts of Windows 10 and 11 (`WindowsContracts.Net.Foundation.UniversalApiContract`, `PrivateAssets="all"`; no Windows SDK target), each in its own partial file (`SystemNotificationCenter.linux.cs`, `.winrt.cs`, `.browser.cs`) like the other platforms; `Routeables.Native` now uses the Razor SDK and its JavaScript lives in `wwwroot`; an Avalonia head that targets `net10.0-windows10.0.19041.0` gets the notification center of the Windows App SDK instead (`Routeables.Avalonia` is built for that target too). **In the browser**, WebAssembly applications that are not Blazor (Avalonia, Uno) use the notification center of the browser too: the module and the service worker of `Routeables.Blazor` moved to `Routeables.Native` (Blazor serves the same files), and `Routeables.Native` talks to it with `JSImport`. The `AppNotificationOptions` of `Routeables.Blazor` is gone: every host uses the one of `Routeables.Native` (namespace `Routeables.Native`), which gained `ServiceWorkerUrl`, `DefaultIcon` and `RequestPermissionOnInitialize`. **macOS** (the plain `net10.0` build, no `net10.0-macos` target) has them too: `UNUserNotificationCenter` through the Objective-C runtime (`Desktop/ObjC.cs`, `SystemNotificationCenter.macos.cs`), for an application in a `.app` bundle; outside a bundle nothing is created. `CreateNotificationAsync` still returns `null` where there is no session bus.

### Changed

- **Floating package versions pinned**: `Microsoft.WindowsAppSDK`, `DeviceRunners.*` (0.1.0-preview.12), and in `Routeables.Test.Uno` `MSTest.TestFramework` (4.5.3) and `Uno.UI.RuntimeTests.Engine` (3.0.0-dev.11), to what a restore resolved. `Microsoft.WindowsAppSDK` is pinned too (1.8.260921001): no version floats any more, and `CentralPackageFloatingVersionsEnabled` is off.

- **Deep links: no scheme is accepted unless it is given** (`RouteableDeepLinks`, `RouteableLinkInbox`). `schemes: null` or an empty list used to accept any scheme (`file:`, `content:`, the protocol of another application); it now accepts none of the application, and only an `http(s)` address of a listed host. **An application that passed no schemes must now pass the ones it owns** (`["myapp"]`); the failed result says so. An address with a user name or a password is refused, and no longer copied into the route. The signatures are unchanged.

- **The history file is never wider than its owner on Unix**: `FileRouteableHistoryStore` creates the file with the mode 600 (it used to write it and restrict it right after, which left a moment when another user of the machine could open it) and the folder it creates with the mode 700.

- **The D-Bus calls of the notifications have a delay**: `AddMatch`, `GetNameOwner` and `CloseNotification` give up after 3 s like the others, so a bus that does not answer does not keep an entry of each call.

- **`RouteableTable.Entries` cannot be changed by a caller**: it is a read-only collection, not the array that the table keeps. The read is still the collection itself, with no copy.

- **The versions of xunit v3 are one**: `xunit.v3.assert` and `xunit.v3.extensibility.core` follow `xunit.v3` (4.0.2) instead of staying on 3.2.2.

- **The router tells a word from a value everywhere**: the menus, the controls of navigation of the hosts, MAUI Shell and the router itself compare routes with the templates the router knows, as the address bar of Blazor does, so `/items/aB` and `/items/Ab` are two pages when the identifier is a token or a slug. The comparison of `RouteableState` and of MAUI Shell goes through the same rule.

- **A saved history cannot give a command**: a route written `-/orders` (go back, then navigate) in a history file is skipped when the history is restored.

- **The default buttons of a modal are translated**: `Validate`, `Cancel` and `Close` of `RouteableViewModel`, and the `Close` button of a dialog without commands, go through `RouteableTexts.Button`.

- **A cancelled menu selection answers "no"**: `SelectEntryAsync(entry, cancellationToken)` cancelled while it waits for another selection used to answer `true` and leave the menu on an entry that was never shown. It now answers `false`, and the menu stays on the entry whose page is being shown.

- **A menu follows the page a guard redirects to**: when the selection of an entry ends on another page (the sign-in page that a guard sends the user to), the menu now selects the entry of that page and shows its title. Before, the redirection was left out while the selection ran, and the menu went back to the entry it had before.

- **The source generator reads fewer assemblies**: the bindings of Android and iOS (`Mono.Android`, `Xamarin.*`, `Java.Interop`) and the graphics libraries (`SkiaSharp`, `HarfBuzzSharp`) are not searched for views and view models any more. A project of MAUI for Android reads tens of thousands of types less at each keystroke.

- **`agent-desktop` is installed in a fixed version** (1.3.1) by the smoke tests of the native samples and by the scripts of `agent-desktop/`.

- **The NuGet versions of the repository are central** (`Directory.Packages.props`): the projects write `<PackageReference Include="..." />` and the versions are in one place. The versions are the ones the projects had; `VersionOverride` stays where two projects asked for different ones (`Routeables.Avalonia` keeps the oldest Avalonia it works with, the generator the oldest Roslyn). The Uno SDK projects and `templates/` stay outside of it. A `.editorconfig` shares the indentation.

- **One rule for "the same route?"** (`RouteAddress`, internal): the router (menu entry lookup, type guards, not-found page, `GoBackToAsync`), `WentTo`, the menus (`RouteableMenuViewModelBase`), the table of routes, the controls of navigation (`RouteTarget`, the Shell tabs of MAUI), the sign-in guard of Blazor and the address bar (`RouteableUrlSync`) used eight different comparisons. They now agree: a leading or closing slash does not count, the words of a path ignore the case, a query ignores the order of its pairs and the case of its names but not of its values, and an escaped address is the plain one. Visible effects: a menu entry is found for the page whatever the case or slashes of its route (`/Orders/` is `/orders`), two entries that differ by their query stay two, `RouteableTable` drops `orders/` as a duplicate of `/orders`, and the sign-in guard no longer redirects a visit of the sign-in page with a `returnUrl` to itself.

- **The address bar of Blazor asks any menu to select an entry**: `IRouteableMenuViewModel.SelectEntryAsync` (a default that sets `SelectedEntry`, which the base classes of `Routeables.Core` already implement). A menu written by hand can answer `false` when a guard keeps the user where they were, and the address is put back; before, only the base classes could.

- **Avalonia uses `Routeables.Native`** for its system notifications instead of Avalonia.Labs.Notifications (removed: on Linux its D-Bus dependency crashed the application at start). Turn them on with `AppBuilder.WithAppNotifications()` (`Routeables.Avalonia`). `Routeables.Avalonia` now also builds for `net10.0-android` and `net10.0-ios`: an Android or iOS head must reference it directly to get them. The desktop has them too (Linux through D-Bus, Windows through the notification area, see above); macOS and the browser do not: `CreateNotificationAsync` returns `null` there. On Android pass the intents to `SystemNotificationCenter.HandleIntent` from the main activity.

- **`Routeables.Native` no longer depends on MAUI Essentials or AndroidX** on Android: it follows the activity in front itself, asks for the notification permission with it, and uses `Notification.Builder`. No `Platform.Init` is needed outside MAUI. Applications build the services (`UseRouteablesServices`) before the first activity, as they do; `NativeDialogs.Initialize()` starts it for a host that does not.
- **The three-button dialog is in `Routeables.Native`** (`NativeDialogs.DisplayThreeButtonsAsync`): MAUI, WinUI 3 and Uno use it (Android alert, Windows App SDK `ContentDialog`, iOS alert or sheet) and draw their own where it has nothing to show.

### Fixed

- **A view that fails to show on the UI thread is shown again** (`RegionBinding.ShowFailed`, used by `RouteableRegion`): when the route change came from another thread, the failure happened after the binding had taken the view for shown, and the same view was never tried again. `RouteableHistoryKeeper` also disposes its cancellation source.

- **Starting with a link and a saved history** (`AddRouteableHistory` and `RouteableLinkInbox`): the history is put back first and the addresses are followed after it. Before, the restoration, which starts by erasing the history, could remove the page that the link had just opened.
- **An absolute coordination whose page throws** (an exception in `OnEnteringAsync`, a cancellation) puts back the page that was shown, as a failed result already did; the regions were left empty.
- **`GoBackAsync(steps)` and `GoBackToAsync`** work out the target once the route change may start, so a route change that is already running cannot make them land on another page (`IRouter.MoveBackAsync`).
- **System notifications**: Windows (plain `net10.0`) no longer reports a notification as closed when its banner leaves the screen, and a notification that is shown again replaces the first one on Linux and Windows instead of adding a second one; the expiration of an updated notification runs from its last display; the identifiers of the notifications no longer start again at 1 at each launch (an old notification of the system could be mistaken for a new one); `NotificationCompleted` is raised on the context of the interface (the one in which `Configure` ran), and never on the thread that reads the D-Bus replies.
- **Menu**: it follows the page by its **route** first, so two entries of the same view model type with other routes (`/products/shoes`, `/products/hats`) are told apart after a Back; two overlapping `GoBackAsync` / `GoForwardAsync` of the menu no longer switch off each other's follow; `SelectEntryAsync` and `SelectAsync` take a `CancellationToken`, which the Blazor address sync passes so that a navigation the browser gave up stops its selection.
- **`IRouteTypeGuard`** compares the template like `GoToAsync` does (case and leading `/` ignored): a menu entry that writes its template another way no longer skips the guard.
- **`MoveBackAsync(steps)`** refuses a number below 1.
- **Regions**: an exception in a view that is shown from another thread (queued on the dispatcher) goes to the error channel instead of ending the application (Avalonia, MAUI, WinUI) or being lost (WPF).
- **Linux notifications**: a connection to the session bus that failed is tried again after 5 seconds (it was kept for the life of the process); showing a notification and asking whether the service is there no longer block the calling thread (`SystemNotificationCenter` waits asynchronously), and a call that is not answered in 3 seconds is forgotten instead of kept; a D-Bus header field that the client does not know is read past (the specification asks for it) instead of dropping the message; the action text is `AppNotificationOptions.DefaultActionText`.
- **Telemetry**: a route that no template names is tagged `(unmatched)` in `routeables.route`, not with its address.

## 2.1.0 - 2026-11-11

### Added

- **Your own container** (DryIoc, Autofac, Lamar...): `services.UseRouteablesContainer(factory)` on WPF, Avalonia, Uno and WinUI 3; `ConfigureContainer` on MAUI and `UseServiceProviderFactory` on ASP.NET Core / Blazor Server are the existing hooks (see the guide on hosts).
- **`[Persist]`** on a view-model property: the value is saved with the history snapshots (`RouteableState.CaptureSnapshots`, the Blazor `PersistentComponentState`, `RouteableLinkInbox`) and read back after the process was killed. A source generator writes the code (no reflection, trim and Native AOT safe). Built-in formats for text, numbers, `bool`, `char`, `Guid`, enums, dates and their `Nullable` forms.
- **Your choice of format** for the other types: `IPersistConverter<T>`, given to one property (`[Persist(Converter = typeof(X))]`) or to every property of a type (`RouteablePersistence.RegisterConverter<T>`). `RouteablePersistence.RegisterJson` is one ready-made converter (System.Text.Json source generation). `RouteablePersistence.MaxValueLength` bounds one value (64 KB by default).
- Diagnostic **`ROUT401`**: a `[Persist]` property that cannot be saved is skipped and explained.
- **Several pages at once** (extensions of `IRouter`): `GoToStackAsync(routes)` rebuilds a stack (deep link, wizard), `GoBackToAsync(route | TViewModel | predicate)` goes back to the nearest earlier page, `GoBackAsync(steps)` goes back several pages in one move.
- **Route qualifiers**: `GoToAsync("-")` goes back one page and `GoToAsync("-/orders")` goes back, then to `/orders`; with `RouteableLink.Route="-"` a back button needs no code.
- **Application lifecycle**: a view model that implements `IRouteableAppLifecycle` is told `OnSleepAsync` / `OnResumeAsync`; `RouteableAppLifecycle` raises them for the shown page of the main router and of each region, and saves the history after a sleep (so `[Persist]` values written at sleep are kept). Raised by the host when a window closes (WPF, Avalonia) and by `Window.UseRouteablesLifecycle(services)` on MAUI; call `SleepAsync()` / `ResumeAsync()` yourself on the other hosts.
- **A page for routes that do not exist**: `services.UseNotFoundRoute("/not-found")`; the address asked for is in the value `notFoundUrl`.
- **Guards run again for the page shown**: `router.RefreshGuardsAsync()` and `router.RefreshGuardsOn(source, provider, properties)` (a sign-out redirects to the login page).
- **A pile of pages for each tab** (WPF, Avalonia, WinUI 3, Uno): `RouteableItem.Region` gives a tab (or a `NavigationViewItem`) a region of its own, which keeps its pages when the user goes to another tab and comes back. On .NET MAUI a `Shell` tab whose route is the name of a registered region already works that way.
- **Closing the tab with unsaved changes** (Blazor): a page that implements `IRouteableUnsavedChanges` makes the browser confirm before the tab is closed or reloaded while `HasUnsavedChanges` is true.
- Diagnostic **`ROUT501`** (information): a `GoToAsync("/route")` with a literal that matches no known route, caught at build time instead of when the line runs.
- ASP.NET Core: a click or a close on a browser notification is reported to the server (`NotificationCompleted`).
- Metric `routeables.guard.duration`, and an option to include the address in the route diagnostics.
- `dotnet new` templates for Blazor, .NET MAUI, Uno Platform (desktop head) and WinUI 3 (`routeables-blazor`, `routeables-maui`, `routeables-uno`, `routeables-winui3`).

- .NET MAUI: a `Shell` tab with a region of its own pushed its route again each time it was selected, on top of the pages opened in it. It now goes to its route only while its region has no page.

- `RouteableReturn` took one instance for the whole application, which every visitor of an ASP.NET Core or Blazor host shared. It now has the lifetime of the routers of the host (one for each visitor there). Call `AddRouteableReturn()` after the registration of the host.
- Modules loaded while running: a service that asks for `IServiceProvider` gets the provider of the module (it found nothing of the module before), `ActivatorUtilities` sees the services of the module, and a service that fails to dispose no longer keeps the others alive.
- `ScopedViewCache`, `RegionLayout.Changed`, `RouteableFormLock`: a view that fails to dispose, a listener that throws, or a subscriber that throws on lock no longer stops the rest (a form could stay locked for ever).
- `RouteableHistoryKeeper` could start saving again after it was disposed; `RouteableLinkInbox` polled again every 30 seconds when no page ever came.
- `RegionTabs` ran its posted actions after `Dispose()`; the dialog queue of Blazor left a dialog asked at the moment of the disposal waiting for ever; the dialog callbacks of ASP.NET Core are guarded like the other hosts'.
- Blazor: an address that is an entry of the menu is accepted only once its guards have answered; the cancellation of a navigation reaches the router; the values of a query string are compared exactly (`?q=ABC` is not `?q=abc`); the script of the unload warning is let go of when the circuit ends while it loads.
- `RouteParser.Build`: the value of a `{**catch-all:type}` is checked against its constraint, like the other placeholders.
- iOS: the delegate of the notification center is kept in a field (the center holds it weakly).
- Tests: the four `xUnit1051` warnings (a cancellation token was not passed).

- .NET MAUI (Windows): a content dialog closed without a button (Escape) returned `default` instead of the close result, as Android does.

- .NET MAUI (iOS, Mac Catalyst): a three-button dialog whose content is neither text nor a `UIView` (a MAUI view) is shown by the content dialog service instead of throwing `NotImplementedException`.

- A value a view was given (`{tab::}` style attribute entry) is no longer overwritten by a view model value whose name differs only by case. Blazor: `?x=1&y=2` and `?y=2&x=1` are the same address.

- .NET MAUI: an iOS alert with no button text could not be closed (the caller waited for ever): it gets an OK button; on Android a missing current activity says so instead of failing with a null reference.

- Tests: the screenshot tests (Avalonia, WPF, Uno, MAUI, Blazor/Playwright) are removed with their CI job and artifacts: no reference image was ever kept, so they were all skipped.

- .NET MAUI: the default button of a modal dialog is the first one shown even when the first command has no name; a modal page refused as it opens frees its caller. Blazor: a browser notification that shares its id with a newer one no longer removes the newer one.

- Restoring the history (`RouteableState.RestoreAsync`, `RestoreSnapshotsAsync`, `RouteableHistoryKeeper`, `RouteableLinkInbox`): when the first saved route cannot be shown (a page that no longer exists, a refusal of a guard) the page that was shown before comes back instead of an empty window, and the keeper replaces the saved file by the page that is there, so the failure does not return at every start.
- An absolute coordination (`/Orders/...`) asks the page shown by each router if it can be left (`CanLeaveAsync`) before it erases the histories, and stops without touching anything when one says no; when a segment then fails, a router that is still empty gets its previous page back.
- ASP.NET Core: `RouteableInteractions.AnswerAsync` ignores an index that is not a button of the dialog (it was posted by the page, anyone can change it) and leaves the dialog waiting; the dialogs, toasts and system notifications of one visitor are changed under a lock (two requests at the same time lost updates), and `Toasts` is a copy.
- Blazor: `RouteableUrlSync` compares the case of the values of an address (`/items/aB` is not `/items/Ab`); the words of the route still ignore it.
- `AddRoutes` called after `AddRegion` registers the default router (the keyed router of the region was taken for it); the history of a scoped region is limited to 50 pages like the one of a scoped router.
- A transient page the router disposed when it left the history is no longer disposed a second time when the scope ends.
- `RefreshGuardsOn` follows a `PropertyChanged` that names no property (everything changed).
- `RouteParser` leaves the fragment out of a route (`/orders/42#top` is `/orders/42`).
- `RouteableLinkInbox` keeps at most 32 addresses while the application is not ready (the oldest are dropped) and drops at once the ones longer than `RouteableDeepLinks.MaxLength`.
- `RouteableHistoryKeeper`: a save that read the history before another one no longer replaces it (the last read is the last written).
- Modules: `RouteableModules.Dispose()` waits for the asynchronous disposal on the thread pool, so a service whose `DisposeAsync` resumes on the interface thread cannot block it.
- `BuildRouteableProvider` validates the registrations while a debugger is attached in the package (the validation was only compiled into a debug build); the route generator no longer pairs a view model with the controls of WPF, Uno or WinUI by name.

### Changed

- ASP.NET Core: `AddRouteablesAspNetCore` is renamed **`UseRouteables`** (and `UseRouteables<TMenu>`), the name of the other hosts. The old names still work for this minor version, marked `[Obsolete]`, and will be removed in the next major version.
- Deep links on the web need the allowed hosts to be configured (`RouteableLinkInbox`, `RouteableDeepLinks`); the path base is honoured and an address that leaves the application is refused.
- The route generator reads only the compiled model of its own assembly and caches its result: an edit that changes no route no longer regenerates its file.
- A guard that returns `null` fails with an explicit error.
- Blazor: a `JSDisconnectedException` raised while the main layout talks to the browser is ignored (the circuit is gone).
